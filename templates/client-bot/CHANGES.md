Основа — бот сайта Intromax: `functions/api/tg.js`, `lead.js`, `chat.js`, `tick.js`, `review.js`, `functions/_lib/rem.js`, `chat.js`, `ai.js`, `kb.js`, `ai/schema.sql`. Файлы сайта не тронуты: шаблон целиком в `templates/client-bot/`.

## Изменено (и почему)

1. **Часовой пояс — параметр, а не «Киев».** `kyivToUtc(date,time)` → `localToUtc(date,time,tz)`. В основе несуществующее время (пропуск часа весной) и повтор часа осенью обрабатывались неявно, двойной итерацией; теперь поведение определено и покрыто тестами: несуществующее → сдвиг вперёд, повторяющееся → первое вхождение. Добавлены `utcToLocal`, `dayRange` (сутки 23/24/25 ч), календарные `addDays`/`weekdayKey`.
2. **Секрет вебхука.** В основе выводился из токена (`sha256('intromax-webhook:' + TG_TOKEN)`), вебхук регистрировался автоматически из `/api/tick`. Здесь — явная переменная `WEBHOOK_SECRET`, регистрация одним вызовом `npm run set-webhook`. Причины: тик не должен иметь права менять вебхук; секрет не должен зависеть от токена; нет скрытой магии при деплое клиенту.
3. **`/api/tick` защищён.** В основе тик открыт («зловживати нема чим»). Здесь он отправляет сообщения клиентам по расписанию, поэтому требует `X-Tick-Secret`; воркер-будильник передаёт секрет.
4. **Хранилище напоминаний: KV → D1.** В основе напоминание — ключ `rem:<код>` в KV, который удаляется после отправки; привязка клиента — через `/start r_<код>`. Для записи это не подходит (нужно «за 24 ч» и «за 2 ч», перенос, отмена, повторы). Теперь напоминания вычисляются из таблицы `appointments`, а факт отправки — `reminders_log (appointment_id, kind)` с «захватом» (`INSERT OR IGNORE`) до отправки: параллельные запуски тика не дублируют, сбой отправки повторяется до 3 раз. KV не нужен вообще.
5. **Время напоминания.** В основе одно «за час» (`BEFORE_MS`). Здесь список `beforeHours` (24 и 2), правила: не слать, если запись сделана позже момента напоминания; при простое крона слать только последнее; отменённым не слать; перенос сбрасывает журнал; один раз после визита — просьба об отзыве (`review.js` основы собирал отзывы формой на сайте — здесь это сообщение со ссылкой).
6. **Заявки.** `lead.js` принимал произвольные поля формы сайта и слал одно сообщение. Здесь заявка — структурированная запись (услуга, мастер, слот, клиент) с кнопками управления и проверкой свободного места в момент записи; уникальный индекс на `(master_id, start_ts)` среди активных записей страхует от гонки.
7. **База знаний и AI.** В основе вопросы клиентов обслуживал AI-агент (`ai.js`, `kb.js`, `ai_kb`, модель Claude). В шаблон перенесена только «статичная» часть: `faq` в `config.json` (кнопки с готовыми ответами). Вызовов моделей, ключей и расходов в шаблоне нет — это отдельная платная опция.
8. **Права.** В основе единственный «оператор» (`TG_CHAT_ID`) определялся равенством chat id. Здесь роли: владелец(цы) (`owner.chatIds` + `TG_CHAT_ID`), мастера (`masters[].chatId`), клиент; каждое действие по кнопке персонала проверяет роль и принадлежность записи, действия клиента — владение записью.
9. **Логи.** Основа не логировала данные намеренно; здесь это закреплено: `safeError` вырезает длинные числа, и тест проверяет, что имя/телефон не попадают в `console`.

## Не перенесено (осознанно)

- Живой чат с сайта (`chat.js`, `api/chat.js`, таблицы `chat/msg/tgm`) — другой продукт.
- AI-агент и база знаний сайта (`ai.js`, `api/ai.js`, `kb.js`, `ai/build-kb.js`).
- Формы сайта (`lead.js`) и отзывы формой (`review.js`) — у клиента нет сайта-формы; вместо них бот.

## Новое в шаблоне

`config.json` + проверка с понятными ошибками; расчёт слотов (перерывы, длительность услуги, паузы, мастера, блокировки, DST); весь клиентский диалог; перенос/отмена клиентом; управление записями владельцем и мастерами, `/сьогодні`, `/завтра`, `/блок`, `/id`; тексты uk/ru с поправками по нишам; тесты на Node с эмулятором Telegram и настоящими SQL; миграции; cron-воркер; скрипт регистрации вебхука; README с развёртыванием, чек-листом и оценкой «дорогих» опций.

## Как проверено

- `npm test` — Node 22, встроенный `node:sqlite`, эмулятор Telegram; результаты и число тестов — в описании PR.
- Локально в настоящем Workers-рантайме (Wrangler 4.157, Miniflare/workerd): `wrangler d1 migrations apply --local`, `wrangler pages dev`; запросы `curl` к `/api/tg` и `/api/tick` (403 без секрета, меню, запись до создания записи в D1, 200 от тика) при мок-сервере вместо Telegram.
- **Не проверялось:** деплой в облако Cloudflare (нет аккаунта и токенов — по условию), работа настоящего Telegram (кнопка «Поділитися контактом», доставка), cron-воркер по расписанию. Эти пункты закрывает чек-лист в README при первом развёртывании.
- `CLAUDE.md` в репозитории отсутствует, следовать было нечему.
