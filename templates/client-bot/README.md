# Шаблон клиентского Telegram-бота записи и заявок

Готовый бот приёма записей для салонов, барбершопов, стоматологий, СТО, ветклиник, косметологов и мебели на заказ.
Cloudflare Pages Functions + D1, чистый JavaScript без зависимостей. Всё, что отличается у клиентов, — в одном файле `config.json`.
Тексты бота для клиентов — украинские (есть и русский вариант: `business.language`).

Основа — рабочий бот сайта Intromax (`functions/api/tg.js`, `tick.js`, `_lib/rem.js` и др.); что взято и что изменено — в [CHANGES.md](CHANGES.md).

## Что умеет

**Клиент (в Telegram):** меню → услуга → мастер (необязательно, есть «будь-хто») → день → свободное время → имя → телефон (кнопка «Поділитися контактом» или вручную) → подтверждение. «Мої записи»: отмена и перенос самим клиентом (не позже, чем за `clientChangeMinHours` до визита). «Послуги та ціни», «Контакти й години», «Часті питання» (из `faq`).

**Владелец и мастера:** новая заявка приходит сразу владельцу и выбранному мастеру с кнопками «✅ Підтвердити / 🔄 Перенести / ❌ Скасувати». Команды `/сьогодні` и `/завтра` — список записей (мастер видит только свои). `/блок` — заблокировать слот или весь день (повторное нажатие снимает). Кнопки на карточках обновляются после действий; клиент получает уведомление о подтверждении, переносе, отмене.

**Напоминания клиенту:** за 24 часа и за 2 часа до визита (настраивается), один раз каждое; по отменённым не идут; после переноса отсчёт начинается заново. Через 2 часа после визита — одна просьба об отзыве со ссылкой из `reminders.reviewUrl`.

**Поддержка Intromax (300 грн/мес) — то, что клиент видит каждый месяц:**
- **Отчёт владельцу 1-го числа** (с `support.reportHour`, по умолчанию 10:00): новые записи и сравнение с прошлым месяцем, подтверждённые визиты, переносы и отмены (клиентом / персоналом), сколько раз просили человека, вопросы, на которые бот не знал ответа (самые частые — списком), доступность сайта. Копия — в `support.chatIds` (чат Intromax). Ровно один раз за месяц; сбой отправки — до 3 попыток.
- **Мониторинг сайта клиента** (`monitor.url`): каждый тик (раз в 5 минут, тот же cron-воркер) — GET сайта. Падение = `monitor.failAfter` неудач подряд (по умолчанию 2) → **одно** сообщение «🔴 Сайт не відповідає» владельцу и Intromax; восстановление → одно «🟢 знову працює, не працював ≈ N хв». История в D1 (`uptime_checks`, `uptime_incidents`) — для % в отчёте.
- **Передача человеку с выжимкой:** кнопка «🙋 Звʼязатися з адміністратором» (в «Часті питання», «Контакти» и в ответе на непонятный вопрос), команда `/admin` или слова «оператор», «людина», «менеджер»… Владельцу уходит карточка: **«Хоче:»** (вопрос клиента) и **«Вже:»** (услуга, мастер, время из незавершённой записи или ближайшая запись) + имя и телефон. Оператор отвечает **реплаем** на карточку — бот пересылает клиенту; клиент дописывает — бот пересылает оператору (живой чат до `/start` или сутки).
- **Журнал «неотвеченных вопросов»:** свободный текст, на который в меню нет ответа (без «привіт», «дякую»; телефоны маскируются), — для отчёта и для пополнения `faq`.

**Защита:** проверка секрета вебхука; ограничение частоты запросов от пользователя (по умолчанию 30 в минуту); токены и секреты только в переменных окружения; персональные данные только в D1, в журналы не пишутся; «бот» видит только то, что нужно роли (клиент не откроет чужую запись, мастер — чужие).

## Развернуть клиенту за ~1 час

Нужно: аккаунт Cloudflare (бесплатного хватает), Node.js 22.13+, Telegram-аккаунт владельца бизнеса.
Токены создаёте вы и вводите сами; в репозиторий и в `config.json` они не попадают.

**1. Копия под клиента (≈3 мин).** Для каждого клиента — отдельная копия и отдельные Cloudflare-ресурсы:
```bash
cp -r templates/client-bot ../clients/<klient>-bot && cd ../clients/<klient>-bot && git init
```

**2. Бот в BotFather (≈5 мин).** В Telegram откройте @BotFather → `/newbot` → имя и username (оканчивается на `bot`) → сохраните токен. Он понадобится как `TG_TOKEN`. Аватар и описание — там же (`/setuserpic`, `/setdescription`).

**3. Конфиг (≈15 мин).** Возьмите ближайший пример из `examples/` и положите как `config.json`; впишите название, часы работы, услуги, мастеров (см. «Конфиг» ниже). Проверка — сразу покажет все ошибки списком:
```bash
cp examples/dental.json config.json
npm run check-config
```
Chat id владельца и мастеров пока не знаете — не страшно, шаг 9.

**4. База D1 (≈5 мин).**
```bash
cp wrangler.toml.example wrangler.toml
npx wrangler login
npx wrangler d1 create <klient>-bot-db
```
`database_id` из вывода впишите в `wrangler.toml` (и поменяйте `database_name`). Затем таблицы:
```bash
npx wrangler d1 migrations apply <klient>-bot-db --remote
```
Уже работающему боту (до поддержки) — та же команда: применится только `0002_support.sql`. Без неё бот и напоминания работают, а отчёт и монитор пишут в лог `tick report` / `tick monitor`.

**5. Проект Pages и секреты (≈10 мин).**
```bash
npx wrangler pages project create <klient>-bot --production-branch=main
openssl rand -hex 24      # запустите дважды: одно значение для WEBHOOK_SECRET, другое для TICK_SECRET
npx wrangler pages secret put TG_TOKEN --project-name <klient>-bot
npx wrangler pages secret put WEBHOOK_SECRET --project-name <klient>-bot
npx wrangler pages secret put TICK_SECRET --project-name <klient>-bot
```

**6. Деплой (≈3 мин).**
```bash
npx wrangler pages deploy public --project-name <klient>-bot
```
Адрес будет `https://<klient>-bot.pages.dev`. Привязка D1 (`DB`) берётся из `wrangler.toml`.

**7. Будильник для напоминаний (≈5 мин).** Pages Functions сами по расписанию не запускаются, поэтому отдельный воркер (как `intromax-tick` у основного сайта):
```bash
cd cron-worker
# в wrangler.toml поменяйте name и TICK_URL = "https://<klient>-bot.pages.dev/api/tick"
npx wrangler deploy
npx wrangler secret put TICK_SECRET      # то же значение, что в шаге 5
cd ..
```

**8. Вебхук (≈2 мин).** Запускается у вас локально, один раз; токен и секрет берутся из окружения и никуда не печатаются:
```bash
TG_TOKEN=<токен> WEBHOOK_SECRET=<секрет> npm run set-webhook -- https://<klient>-bot.pages.dev
```
Скрипт вызывает `setWebhook` (с `secret_token`, `allowed_updates: message, callback_query`), `setMyCommands` и печатает `getWebhookInfo`.

**9. Chat id владельца и мастеров (≈5 мин).** Владелец пишет боту `/id` и получает свой chat id (мастера — так же; для группы — добавить бота в группу и написать там `/id`). Впишите в `config.json`:
`"owner": {"chatIds": [123456789]}` и `"chatId"` у мастеров. Либо один chat id владельца — секретом `TG_CHAT_ID` (можно несколько через запятую). Затем `npm run check-config` и повторный деплой (шаг 6).
> Важно: пока ни `owner.chatIds`, ни `TG_CHAT_ID` не заданы, заявки сохраняются, но **некому приходить** — в логах будет «нет получателей заявок».

**9а. Поддержка (≈5 мин, если клиент платит за поддержку).** В `config.json`: `"monitor": {"url": "https://сайт-клиента"}` и `"support": {"chatIds": [<chat id Intromax>], "contact": "@…"}`. Intromax-аккаунт должен один раз нажать `/start` у бота клиента (и написать `/id`, чтобы узнать chat id) — Telegram не даёт боту писать первым. Отчёт и монитор работают от того же cron-воркера, отдельного ничего не нужно.

**10. Проверка** по чек-листу ниже, затем покажите владельцу `/сьогодні`, `/блок` и кнопки на карточке.

### Переменные окружения

| Имя | Где | Обязательно | Что это |
|---|---|---|---|
| `TG_TOKEN` | секрет Pages (+ локально для `set-webhook`) | да | токен бота от @BotFather |
| `WEBHOOK_SECRET` | секрет Pages (+ для `set-webhook`) | да | 16–256 символов `A-Za-z0-9_-`; Telegram шлёт его в заголовке `X-Telegram-Bot-Api-Secret-Token`. Без него бот не принимает ничего |
| `TICK_SECRET` | секрет Pages **и** секрет воркера | да | защита `/api/tick`: без заголовка `X-Tick-Secret` тик не запускается |
| `TG_CHAT_ID` | секрет Pages | нет | chat id владельца (или несколько через запятую) в дополнение к `owner.chatIds` |
| `DB` | привязка D1 в `wrangler.toml` | да | база |
| `TG_API_BASE` | локально | нет | адрес мок-сервера вместо `api.telegram.org` — только для проверок |

## Конфиг (`config.json`)

Полный рабочий пример — `config.json`; примеры по нишам — `examples/`. Проверка: `npm run check-config`.

| Раздел | Что задаёт |
|---|---|
| `business` | `name`, `niche` (`salon barbershop dental sto vet cosmetology furniture other`), `address`, `phone`, `timezone` (по умолчанию `Europe/Kyiv`), `language` (`uk`/`ru`), `currency` |
| `hours` | часы по дням: `"mon-fri": {"open":"10:00","close":"20:00","breaks":[{"from":"14:00","to":"15:00"}]}`, `"sat": {...}`, `"sun": null` (выходной). Нужны все 7 дней; можно диапазоны. Закрытие — до `24:00`; работа **через полночь не поддерживается** |
| `booking` | `stepMin` (шаг сетки, 30), `minLeadMin` (не раньше чем через…, 60), `horizonDays` (30), `bufferMin` (пауза между записями, 0), `chooseMaster`, `autoConfirm` (запись сразу подтверждена), `clientChangeMinHours` (2), `maxActivePerClient` (3) |
| `services` | `id` (латиница), `name`, `durationMin`, `price` (необязательно), `masters` (кто делает; без поля — все) |
| `masters` | `id`, `name`, `chatId` (чат мастера для заявок), `hours` (свои дни: отличия от общего графика, `null` — выходной), `services` (что делает). Нет мастеров — бот работает как один ресурс (мебель, замер) |
| `owner` | `chatIds` — владельцы (личка или группа) |
| `reminders` | `enabled`, `beforeHours` (`[24,2]`), `reviewUrl` (ссылка на отзыв; нет — не просим), `reviewAfterMin` (120) |
| `limits` / `privacy` | `perMinute` (30) / `retentionDays` (730 — сколько хранить прошедшие записи) |
| `faq` | до 10 пар `{q, a}` — кнопка «Часті питання» |
| `support` | `chatIds` (чаты Intromax: копия отчёта и тревог о сайте), `contact` (подпись в отчёте, например `@intromax_support`), `report` (`true` — отчёт 1-го числа), `reportHour` (10 — не раньше этого часа по местному времени) |
| `monitor` | `url` (сайт клиента; пусто — не проверять), `failAfter` (2 — неудач подряд до тревоги), `timeoutSec` (10), `expectText` (строка, которая должна быть на странице — ловит «сайт открылся, но это заглушка хостинга»), `notifyOwner` (`true`; `false` — тревоги только Intromax) |
| `handoff` | `enabled` (`true`) — кнопка «Звʼязатися з адміністратором», `/admin`, слова «оператор/людина/менеджер», живой чат реплаями. Получатели — владельцы (`owner.chatIds` + `TG_CHAT_ID`) |
| `texts` | любые тексты бота по ключам из `src/texts.js` (HTML только `<b> <i> <u> <code>`). Для СТО, например, `{"master_nom":"Пост","master_acc":"пост"}` |

Подстановки в текстах (`{biz}`, `{details}`, `{time}` …) смотрите в `src/texts.js`. Неверный ключ или HTML сразу даёт ошибку при проверке конфига.

## Чек-лист проверки после запуска

С вашего телефона и с телефона владельца:

1. `/start` у бота — приходит меню; у владельца есть строка «Сьогодні / Завтра / Блок часу».
2. `npm run set-webhook` печатает `setWebhook: ok`, а `getWebhookInfo` — без `last_error_message`.
3. Записаться тестовым клиентом: услуга → (мастер) → день → время → имя → «Поділитися контактом» → «Записатися».
4. Владельцу (и выбранному мастеру) пришла карточка с тремя кнопками. «Підтвердити» → клиенту пришло «підтверджено», кнопка с карточки исчезла.
5. «Перенести» на карточке → новое время → клиент получил сообщение. «Скасувати» → подтверждение → клиент получил сообщение, время снова свободно у клиентов.
6. У клиента: «Мої записи» → перенос и отмена работают; за <`clientChangeMinHours` часов отказывает с телефоном бизнеса.
7. `/сьогодні`, `/завтра` — список; нажатие на запись открывает карточку.
8. `/блок` → день → время: у клиентов слот пропал; повторное нажатие вернуло. «Заблокувати весь день» — день исчез из выбора.
9. Напоминания: сделайте запись на время через ~2,5 часа от сейчас, подтвердите — через 30 минут должно прийти «за 2 години». Либо проверьте воркер вручную: `curl -X POST https://<klient>-bot.pages.dev/api/tick -H "X-Tick-Secret: <секрет>"` → `{"checked":…,"sent":…}`. Без секрета должно быть `403`.
10. Чужой пользователь: нажатие кнопок персонала недоступно, `/сьогодні` у обычного клиента ничего не показывает.
11. В Cloudflare → Pages → проект → Functions → Real-time Logs нет ошибок и нет телефонов/имён клиентов.
12. Поддержка: клиентом напишите «Чи є парковка?» → бот предлагает «Звʼязатися з адміністратором» → нажмите → у владельца карточка «Хоче: … / Вже: …»; ответьте на неё реплаем → текст пришёл клиенту. Мониторинг: временно поставьте `monitor.url` на несуществующий адрес (`https://intromax-down-test.invalid`) и `failAfter: 1`, вызовите тик `curl` из п. 9 → в ответе `"site":"down"` и одно сообщение «Сайт не відповідає»; второй вызов — новых сообщений нет. Верните адрес — следующий тик пришлёт «знову працює».

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| Бот молчит | `getWebhookInfo` (через `npm run set-webhook`): `last_error_message`, `pending_update_count`. Webhook не на тот адрес — повторить шаг 8. Вебхук отвечает `403` → `WEBHOOK_SECRET` в Pages не совпадает с тем, что в `set-webhook`. После смены секретов нужен **новый деплой** |
| `500 Not configured` | не заданы `TG_TOKEN` / `WEBHOOK_SECRET` / привязка `DB` |
| `500 Config error` | ошибка в `config.json`: `npm run check-config` покажет список; в логах Pages то же |
| Бот отвечает «Щось пішло не так» | почти всегда база: не применены миграции (шаг 4, `--remote`). В логах — имя ошибки без данных клиента |
| Заявки не приходят владельцу | не заданы `owner.chatIds` / `TG_CHAT_ID`; владелец не нажал `/start` у бота (Telegram не даёт писать первым); бот удалён из группы |
| Нет напоминаний | воркер `*-tick` не задеплоен или `TICK_URL`/`TICK_SECRET` не совпадают (`wrangler tail` воркера покажет `tick failed 403`); `reminders.enabled=false`; клиент заблокировал бота (3 попытки и стоп); запись сделана позже, чем за 24 ч — тогда «за 24 ч» не шлётся, это нормально |
| «Немає вільних місць» | проверьте `hours`, `horizonDays`, что у услуги есть мастер (`masters`/`services`), нет блока на все дни |
| Время «съехало» на час | `business.timezone` не тот. Весна/осень учитываются сами (покрыто тестами) |
| Нет отчёта 1-го числа / тревог о сайте | применена ли `0002_support.sql` (в логах `tick report` / `tick monitor`); `support.report`, `monitor.url`; Intromax и владелец нажимали `/start` у бота; воркер `*-tick` жив. Отчёт за месяц уходит один раз — повторить: `DELETE FROM reports_log WHERE month='ГГГГ-ММ'` |
| Сайт «лежит» по монитору, а в браузере открывается | сайт за Cloudflare с Bot Fight Mode / защитой от ботов отдаёт `403` запросам из Workers: добавьте исключение для User-Agent `IntromaxUptime` или проверяйте другую страницу; `expectText` чувствителен к регистру |
| Надо отменить чужую запись руками | карточка в `/сьогодні` → «Скасувати». Либо SQL: `npx wrangler d1 execute <db> --remote --command "UPDATE appointments SET status='cancelled', cancelled_by='staff' WHERE id=…"` |

Логи в реальном времени: `npx wrangler pages deployment tail --project-name <klient>-bot`.

## Безопасность и персональные данные

- Имя, телефон и Telegram-username клиента лежат **только** в таблице `clients` (D1). Остальные таблицы хранят `client_id`. Автоочистка: записи старше `privacy.retentionDays` и клиенты без записей удаляются тиком раз в час.
- В логи (`console.error`) попадают только имя ошибки и обрезанное сообщение, где длинные числа заменены на `#`; тексты сообщений, имена и телефоны не пишутся (проверено тестами).
- Telegram видит содержимое чата — это свойство мессенджера. Для политики конфиденциальности клиента: данные нужны для записи, хранятся `retentionDays`, удаляются по запросу (SQL выше или `DELETE FROM clients WHERE tg_id=…` + его записи).
- Журнал поддержки (`events`) хранит текст неотвеченных вопросов (цифры телефонов замаскированы) и chat id клиента — **100 дней**, затем обезличивается (остаются только счётчики для отчётов). Проверки сайта (`uptime_checks`) — тоже 100 дней.
- Кнопки персонала проверяют chat id по каждому нажатию, а не по тому, что кнопку «показали». Если персонал — **группа**, нажимать может любой её участник: следите за составом.
- `/api/tick` и вебхук не принимают запросы без секретов; секреты сравниваются за постоянное время.

## Тесты и локальный запуск

```bash
npm test                 # node --test; нужен Node 22.13+ (используется встроенный node:sqlite)
```
Тесты гоняют **настоящие** SQL на SQLite и эмулятор Telegram (`test/helpers/fake-telegram.js`): в сеть не ходят. Покрыто: слоты (конец дня, перерыв, длинная услуга, полночь, весенний/осенний переход), напоминания (без дублей, не по отменённым, повторы при сбое), разбор конфига (плохой конфиг → понятные ошибки), сценарии клиента и персонала, права, лимит запросов, секрет вебхука, приватность логов, схема и миграции; поддержка (`test/support.test.js`) — отчёт на фикстуре, «одна тревога на падение», выжимка оператору, живой чат, работа без миграции 0002, `check-config` на Windows.

## Ограничения

- Один часовой пояс и одна точка на бота; работа через полночь не поддерживается (закрытие до 24:00).
- Запись `pending` занимает слот, пока владелец не отменит; автоснятия по таймеру нет.
- Защита от двойной записи: проверка перед записью + уникальный индекс на «мастер + начало». Пересечение записей разной длины в один и тот же миг двух клиентов теоретически возможно (окно — миллисекунды); владелец увидит обе карточки.
- Повторяющиеся записи, предоплата, лист ожидания, веб-панель — нет (см. раздел ниже).
- Напоминание — «не больше одного раза»: если воркер упал ровно между захватом и отправкой, оно потеряется (лучше потерять, чем дублировать).
- Мониторинг идёт с серверов Cloudflare раз в 5 минут (частота cron-воркера): длительность падения — с точностью ±5 минут; падение короче `failAfter × 5` минут не заметно. Если упал сам Cloudflare/воркер, монитор молчит (это не внешний независимый пинг).
- Отчёт: переносы и отмены считаются с момента применения `0002_support.sql`; первый отчёт после обновления покажет их неполными. «Новые записи» и «визиты» считаются по таблице записей и верны сразу.
- Живой чат — только текст (фото и стикеры не пересылаются); несколько операторов видят ответы клиента, но не ответы друг друга.
- Тесты и локальный прогон не заменяют проверку на живом боте: чек-лист выше нужно пройти после каждого развёртывания.

## Что НЕ входит и стоит дорого

Оценки — **моя прикидка в часах работы, а не замер**; на цену влияют ваша ставка, готовность клиента (доступы, тексты) и сроки сторонних сервисов. Ориентир для КП: `часы × ставка × 1,3 (запас на согласования и правки)` + постоянные расходы клиента отдельной строкой.

| Что | Почему не входит | Работа | Постоянные расходы клиента |
|---|---|---|---|
| **Instagram Direct через Meta** (тот же бот, но в директе) | Нужны Meta-приложение, бизнес-аккаунт Instagram, привязка к Facebook-странице, проверка бизнеса и **App Review** (разрешения на сообщения); отдельный вебхук и токены с продлением; правила окна ответа и шаблонов Meta; другой формат кнопок (кнопок «как в Telegram» нет — быстрые ответы и карусели). Правила Meta меняются, перед КП перепроверять в актуальной документации | 25–45 ч + ожидание проверки Meta от недель | Обычно нет; возможен платный BSP, если не напрямую |
| **Оплата / предоплата** (Monobank, LiqPay, WayForPay, Telegram Payments) | Своя интеграция у каждого провайдера: создание счёта, подпись callback-ов, статусы (оплачено/возврат/просрочено), освобождение слота по таймеру, возвраты. Для ФОП возможны РРО/ПРРО и чеки — отдельная юридическая часть. Деньги = самая большая ответственность за ошибки | 15–30 ч на один провайдер (+8–15 ч на фискализацию) | Комиссия эквайринга |
| **Голос** (голосовые сообщения → текст, или телефонный голосовой помощник) | Распознавание речи — платный внешний API, нужно понимать «завтра после обеда на стрижку» (разбор намерений, а не кнопки), обработка ошибок и подтверждение. Телефонный бот — отдельный продукт (SIP/телефония, задержки, диалоги) | Голосовые в Telegram: 15–30 ч. Телефонный помощник: 50+ ч | Оплата за минуты распознавания/звонков |
| Синхронизация с **Google Calendar** / CRM клиента | OAuth, двусторонняя синхронизация, конфликты | 10–20 ч | — |
| **Веб-панель** владельца (правка услуг, мастеров, отчёты) | Сейчас всё в `config.json` + Telegram; панель — авторизация, формы, права | 35–70 ч | Хостинг |
| Несколько филиалов / часовых поясов, повторяющиеся записи, лист ожидания | Меняет модель данных и слоты | 10–25 ч за каждое | — |
| Рассылки клиентам (акции, «давно не были») | Лимиты Telegram, согласие на рассылку, отписка | 8–15 ч | — |

Бот Telegram с AI-ответами на вопросы (как на сайте Intromax) тоже не входит: нужен ключ модели, лимиты расходов и база знаний — основа есть в `functions/_lib/ai.js`, перенос ≈ 8–15 ч + расход клиента на токены.
